# Extraction Output JSON Schema

This document describes the JSON produced by the extraction stages:

- Stage 1: `extract_sections.py` converts OCR Markdown verdicts into raw section JSON in `extracted_json/`.
- Stage 2: `extract_sections_2.py` converts Stage 1 JSON into more structured field JSON in `extracted_fields/`.
- Stage 3: `fill_template_aistudio.py` converts Stage 2 JSON into the final AI Studio-filled JSON in `full_aistudio/`.

The skeletons below use each value position as the field description. Real output values are strings, arrays, objects, numbers, `null`, or empty arrays as described.

## Stage 1: `extracted_json/`

Generated by `data_create/extract_sections.py` from `.md` files. Only records with no mandatory missing fields are saved.

```json
{
  "filename": "Original Markdown filename, including the .md extension.",
  "Bi_cao": "Raw Markdown/text section from the trial-date line up to the related-parties section if present, otherwise up to NỘI DUNG VỤ ÁN. Usually contains case opening, trial metadata, defendants, and sometimes defense counsel.",
  "Lien_quan": "Raw Markdown/text section for other participants such as victims, civil plaintiffs/defendants, people with related rights and obligations, and witnesses. Null when no related-party boundary is detected.",
  "NOI_DUNG_VU_AN": "Raw Markdown/text section from the NỘI DUNG VỤ ÁN heading up to the NHẬN ĐỊNH section. Contains case facts, investigation narrative, indictment/prosecution position, and party statements depending on the verdict.",
  "NHAN_DINH": "Raw Markdown/text section from the NHẬN ĐỊNH CỦA TÒA ÁN or equivalent heading up to the QUYẾT ĐỊNH heading. Contains the court's reasoning and assessment.",
  "QUYET_DINH": "Raw Markdown/text section from the QUYẾT ĐỊNH heading to the end of the Markdown file. May include recipient/signature blocks because Stage 1 preserves the full tail section.",
  "_missing": "List of missing mandatory extraction fields found while processing the source file. Saved Stage 1 JSON normally has an empty list because failures are skipped.",
  "_lines": {
    "trial_date": "Zero-based source line index where the trial-date/opening line was found, or -1 during failed extraction.",
    "lien_quan": "Zero-based source line index where the related-party boundary was found, or -1 when absent/not valid.",
    "noi_dung": "Zero-based source line index where the NỘI DUNG VỤ ÁN heading was found, or -1 during failed extraction.",
    "nhan_dinh": "Zero-based source line index where the NHẬN ĐỊNH heading was found, or -1 during failed extraction.",
    "quyet_dinh": "Zero-based source line index where the QUYẾT ĐỊNH heading was found, or -1 during failed extraction."
  }
}
```

### Stage 1 Field Notes

- Mandatory fields for saving are `Bi_cao`, `NOI_DUNG_VU_AN`, `NHAN_DINH`, and `QUYET_DINH`.
- `Lien_quan` is optional and can be `null`.
- `_missing` and `_lines` are diagnostics from the section-boundary extractor, not legal content.
- Section fields preserve Markdown headings, bullets, OCR artifacts, and original line breaks.

## Stage 2: `extracted_fields/`

Generated by `data_create/extract_sections_2.py` from Stage 1 JSON. The script detects case type, skips `phuc_tham` records, and saves only non-appeal records where the key extracted fields are present.

```json
{
  "filename": "Original Markdown filename copied from Stage 1.",
  "case_type": "Detected case type. Expected values are so_tham, phuc_tham, or unknown; saved Stage 2 files normally contain so_tham because phuc_tham records are skipped.",
  "Danh_sach_bi_cao": [
    "One raw text block per defendant extracted from the Stage 1 Bi_cao section. Each item preserves the defendant's available identity/background text and may include surrounding opening text when the splitter cannot isolate only the name block."
  ],
  "Nguoi_tham_gia": "Raw related-participants text copied from Stage 1 Lien_quan. Includes victims, related parties, witnesses, and similar participant groups. Null when Stage 1 Lien_quan is null.",
  "Noi_dung_vu_an": {
    "Qua_trinh_dieu_tra": "First part of the Stage 1 NOI_DUNG_VU_AN text after removing the NỘI DUNG VỤ ÁN heading. Usually contains the investigation/factual narrative before the indictment or prosecutor marker.",
    "Ket_luan_cac_ben": "Remaining part of the Stage 1 NOI_DUNG_VU_AN text starting at the indictment/prosecutor marker. Usually contains prosecution conclusions, party statements, and trial-position text."
  },
  "Nhan_dinh_cua_toa_an": {
    "[1]": "Text of court-assessment point [1], excluding the [1] marker itself.",
    "[2]": "Text of court-assessment point [2], excluding the [2] marker itself.",
    "[n]": "Additional dynamic numbered assessment points. Keys are bracketed numbers found in the source, such as [3], [4], [10], etc. If no numbered markers are found, the whole NHAN_DINH section is stored under [1]."
  },
  "QUYET_DINH": "Raw decision/verdict text copied from Stage 1 QUYET_DINH. In the current pipeline this is not split into sub-fields and is not passed through the clean_quyet_dinh helper."
}
```

### Stage 2 Field Notes

- `Danh_sach_bi_cao` is a list of strings. Saved files require it to be non-empty.
- `Noi_dung_vu_an.Qua_trinh_dieu_tra` and `Noi_dung_vu_an.Ket_luan_cac_ben` are saved as strings when extraction succeeds. If no indictment/prosecutor marker is found, `Ket_luan_cac_ben` can be `null` in intermediate results, and such records are not saved by the default script.
- `Nhan_dinh_cua_toa_an` is an object with dynamic keys, not a fixed set of fields. The keys come from numbered markers in the court reasoning section.
- `QUYET_DINH` remains raw text in saved Stage 2 output. Although `extract_sections_2.py` contains helper functions for verdict sub-fields such as `Can_cu_dieu_luat`, `Pham_toi`, `Phat_tu`, `Phat_tien`, and `An_phi`, those fields are not emitted by `extract_fields()` in the current script.

## Stage 3: `full_aistudio/`

Generated by `data_create/fill_template_aistudio.py` from Stage 2 JSON. This stage copies some Stage 2 fields directly and fills defendant, prosecutor-recommendation, and first-instance decision fields through the `LLMExtractionOutput` Pydantic schema.


### Stage 3 Field Notes

- `THONG_TIN_CHUNG.Thong_Tin_Bi_Cao`, `De_Nghi_Cua_Vien_Kiem_Sat`, and `PHAN_QUYET_CUA_TOA_SO_THAM` are arrays because one case can contain multiple defendants.
- Optional LLM fields are written with `model_dump(exclude_none=True)`, so null optional fields inside those arrays are usually omitted rather than emitted as `null`.
- `NOI_DUNG_VU_AN` and `NHAN_DINH_CUA_TOA_AN` are copied from Stage 2, not newly normalized by the LLM.
- `Thong_Tin_Nguoi_Tham_Gia_To_Tung` is copied from Stage 2 `Nguoi_tham_gia`; the script defaults to an empty string when the key is absent.
- `_usage` is emitted only for successful model extraction and records provider/model/token/cost metadata.
- The imported schema includes `Xu_Ly_Vat_Chung`, but the current `fill_template_aistudio.py` script does not copy it into `stage3_data`, so it is not part of the saved Stage 3 output.

## Pipeline Summary

```text
ocr_marker_fixed/*.md
  -> extract_sections.py
  -> extracted_json/*.json
  -> extract_sections_2.py
  -> extracted_fields/*.json
  -> fill_template_aistudio.py
  -> full_aistudio/*.json
```

Stage 1 is a section-boundary extraction pass. Stage 2 is a field-structuring pass over the Stage 1 sections. Stage 3 is the final template-filling pass using AI Studio with OpenRouter fallback.
